# 路線ID Apps Script

替龍洞路線 Google Sheet 的每條路線產生一個**固定不變的路線ID**（6 碼短碼，例如 `7kq2mx`），並保護它不被手動修改。
App 用這個 ID 記錄使用者的收藏與攀登紀錄，所以之後改路線名稱、改編號（例如新版指南書重新編號），紀錄都不受影響。

## 安裝（只需要做一次）

建議用 TOCC 的公用帳號安裝：自動保護會以安裝者的身分執行，安裝者需要一直保有這份 Sheet 的編輯權限。

1. 打開路線 Sheet，選單 **擴充功能 → Apps Script**。
2. 把編輯器裡的程式碼全部刪掉，貼上 [`RouteIds.gs`](RouteIds.gs) 的全部內容，按 **儲存**（磁碟圖示）。
3. 回到 Sheet，**重新整理頁面**，上方選單會多出 **路線ID**。
4. 點 **路線ID → 啟用自動保護**。
   - 會要求授權：選帳號 →（若出現「Google 尚未驗證這個應用程式」）**進階 → 前往「…」（不安全）** → **允許**。
     這是你自己貼上的程式；授權內容是編輯這份 Sheet，以及讀取已發布的網站資料（用來還原 ID）。
5. 點 **路線ID → 補上缺少的 ID**。每個區域分頁的**最右邊**會多一欄「路線ID」。
6. 等下一次同步（每天 03:00，或到 GitHub Actions 手動執行「Data sync」），合併同步 PR 後 App 就會改用新的 ID。

## 之後的使用

- **新增路線**：填好路線編號和名稱，「路線ID」會自動產生。
- **改名稱、改編號**：直接改，ID 不受影響。
- **刪除路線**：直接在 Sheet 刪掉即可。同步時會自動放行，刪了哪些路線會記在同步紀錄（commit 訊息）裡。
- **「路線ID」欄不能手動修改**：任何人打字、清除、貼上改到這一欄，都會立刻還原，右下角會出現提示。
  還原的來源依序是：編輯前的值 → 已發布的網站資料（同分頁、同編號、同名的路線）。
  例外：同步失敗的錯誤訊息要你「把它改回 <原本的ID>」時，直接在儲存格打上原本的 ID，會被接受、不會還原。
- **複製整列來新增路線**：複製過來的 ID 會和原路線重複，程式會自動換一個新的。
- 如果覺得哪裡怪怪的，點 **路線ID → 補上缺少的 ID**：會找回缺少的 ID、修正重複的 ID。

## 最後一道防線

同步到 App 時，匯入程式還會再檢查一次，以下情況會停止同步，網站維持上一版資料，GitHub 會寄通知給 repo 管理員：

- 有路線缺 ID、ID 格式不對、ID 重複
- 同一條路線（同區域、同編號、同名）的 ID 變了：錯誤訊息會寫出原本的 ID
- 一次有超過 10 條路線消失：多半是誤刪（例如整頁被清空）。確定要大量刪除，把錯誤訊息列出的 ID 加進 repo 的 `scripts/retired-ids.ts`

## 注意

- 安裝者的帳號若失去這份 Sheet 的編輯權限，自動保護會停止。請改用其他帳號重新執行「啟用自動保護」。
- ID 由 `23456789abcdefghjkmnpqrstuvwxyz` 組成（不含容易看錯的 0/o、1/l/i），全 Sheet 不重複。
